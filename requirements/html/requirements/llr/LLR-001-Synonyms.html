    LLR-SYN-1
    1. Optional config_path Constructor Parameter
    UID: LLR-SYN-1
    MID: 8ce759fdbcff49d7bc57cf22fedc3874
    RELATIONS (Parent):
    • HLR-007 Configurable Synonym Loading
    STATEMENT:

    The StandardizeName class shall accept an optional config_path parameter of type Path | str | None in its constructor. When the parameter is None (default), built-in default synonyms shall be used.
    RATIONALE:

    A single optional parameter preserves the existing call signature and enables opt-in configuration without forcing changes on existing callers.
    PRIORITY:

    High

    LLR-SYN-7
    7. Overlapping Synonym Detection
    UID: LLR-SYN-7
    MID: e1d8d3802013494dbe08b6faa31a5006
    RELATIONS (Parent):
    • HLR-009 Synonym Configuration Validation
    STATEMENT:

    The system shall detect and reject configurations in which the same synonym string appears in more than one entry. Such overlap shall raise an AssertionError or ValueError identifying the conflicting synonym.
    RATIONALE:

    Overlapping synonyms produce non-deterministic normalization results; rejecting them at load time enforces correctness.
    PRIORITY:

    High

    UID: LLR-SYN-11
    MID: a1d9a9d64ce64d4daf02a182cbe96be1
    RELATIONS (Parent):
    • HLR-007 Configurable Synonym Loading
    STATEMENT:

    The system shall match exercise name inputs to synonyms in a case-insensitive manner, converting the input to a canonical form before lookup.
    RATIONALE:

    Users enter exercise names in varying capitalization; case-insensitive matching reduces friction and avoids missed normalization.

    LLR-SYN-12
    11. Path Object and String Path Acceptance
    UID: LLR-SYN-12
    MID: 763a15127ce24b37a5f3e549fb8caca1
    RELATIONS (Parent):
    • HLR-007 Configurable Synonym Loading
    STATEMENT:

    The config_path parameter shall accept both pathlib.Path objects and plain string paths interchangeably, converting strings to Path internally as needed.
    RATIONALE:

    Supporting both types matches Python idioms and avoids forcing callers to convert their path representations.
    PRIORITY:

    Low
    LLR-SYN-13
    12. Per-Instance Independent Configuration
    UID: LLR-SYN-13
    MID: 6331f457fac84f78ab337871810cb8c6
    RELATIONS (Parent):
    • HLR-011 Synonym-Based Internationalization
    STATEMENT:

    Each StandardizeName instance shall maintain its own synonym mapping independently, so that multiple instances with different config_path values may coexist in the same process without interference.
    RATIONALE:

    Independent instances are required to enable simultaneous parsing with different synonym sets (e.g., per-language parsers).
    PRIORITY:

    Medium
    LLR-SYN-14
    13. Eager Load at Initialization
    UID: LLR-SYN-14
    MID: 7196371908c4451d90dece229e3deffd
    RELATIONS (Parent):
    • HLR-009 Synonym Configuration Validation
    STATEMENT:

    The system shall load and validate the synonym configuration during __init__ (eagerly), not deferred to the first use of the run() method.
    RATIONALE:

    Eager loading ensures that configuration errors surface immediately at construction time rather than mid-parse, simplifying error handling for callers.
    PRIORITY:

    Medium
