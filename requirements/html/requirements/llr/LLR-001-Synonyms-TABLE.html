    • HLR-007 Configurable Synonym Loading
    LLR-SYN-1
    Optional config_path Constructor Parameter

    The StandardizeName class shall accept an optional config_path parameter of type Path | str | None in its constructor. When the parameter is None (default), built-in default synonyms shall be used.

    A single optional parameter preserves the existing call signature and enables opt-in configuration without forcing changes on existing callers.

    YAML Synonym File Loading

    The system shall load synonym configurations from files with .yaml or .yml extensions by parsing them as YAML documents using a standards-compliant YAML parser.

    LLR-SYN-4
    Unsupported Format Error

    The system shall raise a ValueError with a descriptive message when the config_path refers to a file whose extension is neither .yaml, .yml, nor .json.

    An explicit error on unsupported formats prevents silent failures and guides users toward supported alternatives.
    REQUIREMENT 5 LLR-SYN-5 681b72dfa23f4555a84cca6c42d16513 Parents:
    • HLR-009 Synonym Configuration Validation
    LLR-SYN-5
    Root Key Validation

    The system shall validate that the parsed configuration document contains a top-level synonyms key whose value is a list. A missing key or non-list value shall raise a ValueError with a descriptive message.
    REQUIREMENT 6 LLR-SYN-6 a868f7bdef404f0d8c34b0332c511ba5 Parents:
    • HLR-009 Synonym Configuration Validation
    LLR-SYN-6
    Synonym Entry Structure Validation

    The system shall validate that each entry in the synonyms list contains exactly a clean key (string) and a synonyms key (list of strings). Missing or incorrectly typed fields shall raise a ValueError.
    REQUIREMENT 7 LLR-SYN-7 e1d8d3802013494dbe08b6faa31a5006 Parents:
    • HLR-009 Synonym Configuration Validation
    LLR-SYN-7
    Overlapping Synonym Detection

    The system shall detect and reject configurations in which the same synonym string appears in more than one entry. Such overlap shall raise an AssertionError or ValueError identifying the conflicting synonym.

    Overlapping synonyms produce non-deterministic normalization results; rejecting them at load time enforces correctness.
    REQUIREMENT 8 LLR-SYN-8 baa0423a5c3d413b8a950a7d59382985 Parents:
    • HLR-009 Synonym Configuration Validation
    LLR-SYN-8
    Duplicate Clean Name Detection

    The system shall detect and reject configurations in which the same clean name appears in more than one entry. Such duplication shall raise a ValueError identifying the duplicate clean name.
    REQUIREMENT 9 LLR-SYN-9 63036d4bb84b4891923a630b0820790e Parents:
    • HLR-009 Synonym Configuration Validation
    LLR-SYN-9
    Missing File Error

    The system shall raise a FileNotFoundError with a descriptive message when the specified config_path does not refer to an existing file.
    REQUIREMENT 10 LLR-SYN-11 a1d9a9d64ce64d4daf02a182cbe96be1 Parents:

    LLR-SYN-11
    Case-Insensitive Synonym Matching

    The system shall match exercise name inputs to synonyms in a case-insensitive manner, converting the input to a canonical form before lookup.

    Users enter exercise names in varying capitalization; case-insensitive matching reduces friction and avoids missed normalization.
    REQUIREMENT 11 LLR-SYN-12 763a15127ce24b37a5f3e549fb8caca1 Parents:
    • HLR-007 Configurable Synonym Loading
    LLR-SYN-12
    Path Object and String Path Acceptance

    The config_path parameter shall accept both pathlib.Path objects and plain string paths interchangeably, converting strings to Path internally as needed.

    Supporting both types matches Python idioms and avoids forcing callers to convert their path representations.
    REQUIREMENT 12 LLR-SYN-13 6331f457fac84f78ab337871810cb8c6 Parents:
    • HLR-011 Synonym-Based Internationalization
    LLR-SYN-13
    Per-Instance Independent Configuration

    Each StandardizeName instance shall maintain its own synonym mapping independently, so that multiple instances with different config_path values may coexist in the same process without interference.

    Independent instances are required to enable simultaneous parsing with different synonym sets (e.g., per-language parsers).
    REQUIREMENT 13 LLR-SYN-14 7196371908c4451d90dece229e3deffd Parents:
    • HLR-009 Synonym Configuration Validation
    LLR-SYN-14
    Eager Load at Initialization

    The system shall load and validate the synonym configuration during __init__ (eagerly), not deferred to the first use of the run() method.

    Eager loading ensures that configuration errors surface immediately at construction time rather than mid-parse, simplifying error handling for callers.
